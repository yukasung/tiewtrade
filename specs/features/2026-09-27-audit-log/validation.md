## เทสต์ที่ต้องมี

- **ตัวเลขจริง:** จำนวนเงินใน `details` ที่คำนวณมือแล้วเทียบ — ค่าทศนิยม 18 ตำแหน่ง,
  ค่าลบ, ศูนย์ พร้อมเขียนที่มาของคำตอบไว้
- **คุณสมบัติ (hypothesis):**
  - บันทึกที่เขียนลงไปแล้วอ่านกลับได้ค่าเดิมทุกช่อง สำหรับทุกเหตุการณ์ที่ถูกต้อง
  - `details` ที่มีคีย์ต้องห้ามอยู่ที่ความลึกใดก็ตาม **ต้องถูกปฏิเสธเสมอ**
  - ไม่ว่าลำดับผู้ใช้เป็นอย่างไร ผู้ใช้หนึ่งไม่เคยเห็นบันทึกของอีกคน
- **ความปลอดภัยการเทรด:**
  - แก้ ลบ ล้าง ไม่ได้ ทั้งที่ตารางแม่และที่พาร์ทิชัน ทั้งสองชั้น (V-2 ถึง V-7)
  - การกระทำที่แตะข้อมูลกับบันทึกอยู่ใน transaction เดียวกัน (V-28, V-29)
  - ไม่มี secret และไม่มีข้อมูลระบุตัวตนในบันทึก (V-24 ถึง V-27)

**เขียนเทสต์โดยคิดค่าที่คาดหวังขึ้นใหม่เอง ห้ามลอกจากโค้ดที่กำลังทดสอบ**

## ตรวจด้วยมือ

1. `env -u POSTGRES_VERSION docker compose --env-file config/postgres.env up -d --build --wait`
   บนฐานข้อมูลเปล่า → migration ผ่านครบถึง `0004`
2. `SELECT * FROM tiewtrade_append_only_tables;` → เห็น `audit_events` และพาร์ทิชันทั้งหมด
3. ต่อด้วยบทบาท `tiewtrade_api` แล้วลอง `UPDATE audit_events SET action = 'x';` → ถูกปฏิเสธ
4. ลอง `TRUNCATE audit_events_2026_09;` (ชื่อพาร์ทิชันตรง ๆ) ด้วย `tiewtrade_migrator`
   → ถูกปฏิเสธด้วย trigger
5. สร้างผู้ใช้ใหม่ผ่านโค้ด แล้วอ่าน `audit_events` ด้วย identity ของผู้ใช้นั้น
   → เห็นแถว `USER_CREATED` หนึ่งแถว และอ่านด้วย identity ของคนอื่น → ไม่เห็น
