# Preserve historical viewport — 2026-10-14

Fix within approved P-H3 viewport-anchor behavior; no requirement or backend changes.

Previously each redraw restored `getVisibleRange()` through `setVisibleRange()`.
The installed Lightweight Charts API documents that these methods clamp to available
data and cannot extrapolate blank space. Replacing a bounded history page could
therefore alter pan/zoom rather than preserve the user's viewport.

The chart now captures the fractional logical range before redraw and translates it
by the index displacement of a timestamp shared by the old and new page. This keeps
the same candle anchor and zoom, including whitespace beyond either page edge.
Initial loading, TF changes and explicit reset retain their existing behavior.

Validation:

- 18 targeted tests passed: 15 panel tests and 3 viewport tests. Coverage includes
  live redraw, fractional pan, empty space, older/newer pages, sliding latest window,
  and zoom wider than the overlapping page segment.
- TypeScript and scoped ESLint passed; frontend rebuilt/restarted.
- Browser-only auth/data fixtures with the actual chart renderer: old logical range
  25.5–130.75 became 825.5–930.75 after prepending the older page. The same timestamp
  remained at x=300.76px after 6.5 seconds of update cycles: drift **0px**, no JS errors.
  [Recorded coordinates](2026-10-14-viewport.json).
- Browser instrumentation was injected only into the test response, not production code.
  Real registration was rate-limited, so this smoke used isolated browser fixtures;
  it does not establish exchange/history completeness. No DB fixtures or orders.
- No full suite or benchmark. Existing release validation remains pending.
