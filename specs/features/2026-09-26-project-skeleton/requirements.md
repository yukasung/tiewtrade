# F-01 วางโครง repo, เครื่องมือ, CI — Requirements

สถานะ: **Proposed** — รอเจ้าของอนุมัติ
วันที่: 2026-09-26
งานใน roadmap: F-01

---

## ทำไมต้องมี

ตอนนี้ repo มีแต่เอกสาร ไม่มีโค้ดเลยสักบรรทัด ทุกงานที่เหลือใน roadmap
ต้องการที่วางโค้ดและด่านตรวจที่ทำงานอัตโนมัติก่อน

ถ้าเริ่มเขียน F-02 (ชนิดข้อมูลเงิน) โดยยังไม่มีด่านตรวจ จะไม่มีอะไรบังคับกฎที่ตกลงกันไว้:
ห้ามใช้ `float` กับเงิน, `core` ต้องไม่พึ่งอะไร, ชั้นต่าง ๆ ห้าม import ข้ามกัน
กฎพวกนี้จะกลายเป็นข้อตกลงด้วยปากเปล่า ซึ่ง `specs/standards/architecture.md`
ระบุชัดว่าต้องบังคับด้วย CI ไม่ใช่ด้วยการรีวิว

**คนที่เดือดร้อนถ้าไม่มี** — ทุกงานหลังจากนี้ และเจ้าของ เพราะกฎความปลอดภัย
ที่ตัดสินกันมาทั้งหมดจะไม่มีที่ยืนจริง

## ขอบเขต

### ทำ

**repo เดียว** (เจ้าของตัดสิน 2026-09-27) เก็บทั้งหลังบ้านและหน้าบ้านไว้ที่เดียว
เหตุผล: ชนิดข้อมูลของ API สองฝั่งต้องตรงกันเสมอและตรวจได้ใน commit เดียว
และงานที่แตะสองฝั่งยังเป็น branch เดียวได้ตามกฎใน `AGENTS.md`

- โครงโฟลเดอร์ของโค้ดตามชั้นใน `standards/architecture.md`
- ตั้งเครื่องมือภาษา Python และการจัดการ dependency
- ด่านตรวจอัตโนมัติครบทุกด่านที่ `standards/testing.md` หัวข้อ 1 กำหนด
- CI ที่รันด่านเหล่านั้นทุกครั้งที่ push
- เทสต์ตัวอย่างอย่างน้อยหนึ่งตัวต่อด่าน เพื่อพิสูจน์ว่าด่านทำงานจริง
  **รวมเทสต์ที่จงใจให้แดง** เพื่อยืนยันว่าด่านจับได้จริง ไม่ใช่ผ่านเพราะไม่มีอะไรให้ตรวจ

### ไม่ทำ

- ไม่เขียนตรรกะธุรกิจใด ๆ ไม่ว่าเรื่องเงิน ออเดอร์ หรือกลยุทธ์
- **ไม่ออกแบบส่วนต่อประสานของ `venues`** — สร้างแค่โครง package ว่างกับกฎการพึ่งพา
  การกำหนดว่ามีบริการอะไรและหน้าตาอย่างไร เป็นงาน F-33 (ดู RQ-5)
- ไม่ต่อ Binance
- ไม่สร้างตารางฐานข้อมูลจริง (เป็นงานของ F-03)
- **ไม่ทำหน้าจอผู้ใช้จริง** — หน้าบ้านมีแค่หน้าเปล่าหนึ่งหน้าตาม RQ-17
  ไม่มีเมนู ไม่มีการจัดหน้าตา ไม่มีระบบแปลภาษา ไม่มี component กลาง
  (งานหน้าจอจริงเริ่มที่ F-12)
- ไม่นำขึ้นเครื่องจริง (เป็นงานของ F-31)
- **Docker Compose ยังไม่ครบทุก service** — มีเฉพาะที่งานนี้ใช้ตาม RQ-18
  `engine` และ `market-data` ยังไม่มีโค้ดให้รัน จึงยังไม่ใส่
- **ยังไม่ใส่ PostgreSQL และ Redis** ใน Docker Compose (เจ้าของตัดสิน 2026-09-27)
  งานนี้ยังไม่มีตารางและไม่มีคิว ของที่ใส่แล้วไม่มีใครใช้จะไม่มีใครรู้ว่าพัง
  จนถึงวันที่เริ่มใช้จริง PostgreSQL จะถูกใส่ตอน F-03 ที่มีตารางจริง

## ข้อที่ผมเพิ่มเอง ไม่ได้มาจากสเปก

**RQ-12 เก็บกรณีที่ละเมิดกฎไว้ถาวร พร้อมการตรวจว่าด่านปฏิเสธกรณีนั้น**

สเปกบอกว่าต้องมีด่านตรวจ แต่ไม่ได้บอกว่าต้องพิสูจน์ว่าด่านทำงาน

ด่านที่ตั้งผิดจะขึ้นเขียวตลอดโดยไม่ตรวจอะไรเลย ซึ่งอันตรายกว่าไม่มีด่าน เพราะทำให้เชื่อผิด ๆ
เช่น ตั้ง import-linter แล้วไม่ได้ใส่กฎ หรือ mypy ที่ไม่ได้เปิดโหมดเข้ม

**ฉบับแรกของข้อนี้เขียนว่า "ทดสอบแล้วลบหรือปิดไว้" ซึ่งผิด** เพราะหลักฐานจะเหลืออยู่แค่
ตอนตั้งระบบครั้งแรก ใครมาแก้ config ทีหลังจนด่านเสีย จะไม่มีอะไรจับได้
แก้เป็นเก็บไว้ถาวรแล้วตรวจอัตโนมัติว่าด่านยังปฏิเสธกรณีนั้นอยู่
(แก้ตามรีวิว `specs/reviews/2026-09-26-project-skeleton-requirements.md` ข้อ 2)

ถ้าเจ้าของไม่เห็นด้วยให้ตัดข้อนี้ออกได้

## สิ่งที่งานนี้ **ไม่ได้** ทำให้เกิดขึ้น

หลังจบ F-01 ระบบยังทำอะไรไม่ได้เลยในสายตาผู้ใช้ — สิ่งที่เห็นบนหน้าจอคือหน้าเปล่า
หนึ่งหน้าที่แสดงผลจาก API หนึ่งเส้น ไม่มีข้อมูลการเทรด ไม่มีเมนู ไม่มีอะไรให้กด
สิ่งที่ได้คือ **ที่วางโค้ด ด่านตรวจที่ทำงานจริง และทางเดินจากหลังบ้านถึงหน้าบ้านที่พิสูจน์แล้ว**

ถ้าเจ้าของคาดหวังว่าจะเห็นอะไรบนหน้าจอหลังงานนี้ แสดงว่าขอบเขตไม่ตรงกัน และต้องคุยก่อน
