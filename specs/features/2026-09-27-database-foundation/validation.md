## เทสต์ที่ต้องมี

- **ตัวเลขจริง:** ค่าเงินที่คำนวณมือแล้วเทียบ — ค่าที่ทศนิยมครบ 18 หลัก, ค่าที่ขอบ `MAX_ABS`,
  ค่าลบ, ค่าศูนย์ พร้อมเขียนที่มาของคำตอบไว้ (`testing.md` หัวข้อ 2)
- **คุณสมบัติ (hypothesis):**
  - เขียนลงแล้วอ่านกลับได้ค่าเดิมเสมอ สำหรับทุกค่าที่ `Money` ยอมรับ
  - ค่าที่ `Money` ปฏิเสธ ฐานข้อมูลต้องปฏิเสธด้วย และกลับกัน (V-25)
  - ไม่ว่าลำดับผู้ใช้ในหนึ่ง connection เป็นอย่างไร ผู้ใช้หนึ่งไม่เคยเห็นแถวของอีกคน
- **ความปลอดภัยการเทรด:** งานนี้ยังไม่ส่งออเดอร์ เทสต์ที่เกี่ยวคือ
  - `api` **อ่านคอลัมน์ secret ไม่ได้ แต่เขียนได้** (ทดสอบบนตารางทดสอบของงานนี้ — RQ-6)
  - บทบาทข้าม RLS **อ่านคอลัมน์ secret ไม่ได้** (Q-3 เงื่อนไข ก)
  - ทุกกรณีของ V-15 ถึง V-20 ซึ่งเป็นรากของ "บันทึกแล้วหายไม่ได้"
    (`trading-safety.md` หัวข้อ 10)

**เขียนเทสต์โดยคิดค่าที่คาดหวังขึ้นใหม่เอง ห้ามลอกจากโค้ดที่กำลังทดสอบ** (`testing.md` หัวข้อ 2)

## ตรวจด้วยมือ

1. `env -u POSTGRES_VERSION docker compose --env-file config/postgres.env up -d --build --wait` บนเครื่องเปล่า → ฐานข้อมูลขึ้น, migration รันเอง,
   `/health` ตอบ `ok`
2. ต่อฐานข้อมูลด้วยบทบาท `tiewtrade_api` แล้วลอง `SELECT * FROM users` โดยไม่ตั้ง identity
   → ต้องได้ศูนย์แถว **ไม่ใช่เห็นทุกแถว**
3. ลอง `DROP TABLE users` ด้วยบทบาท `tiewtrade_api` → ต้องถูกปฏิเสธ
4. ลอง `UPDATE` และ `TRUNCATE` ตารางที่เปิดกลไก append-only ด้วยบทบาท `tiewtrade_migrator`
   → ต้องถูกปฏิเสธด้วย trigger
5. `alembic downgrade base` แล้ว `alembic upgrade head` → ผ่านทั้งสองทาง
