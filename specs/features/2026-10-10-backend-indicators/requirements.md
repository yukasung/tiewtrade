## เลื่อน full validation เพื่อพัฒนาต่อ — Approved 2026-10-24

เจ้าของอนุมัติด้วย “approve” ให้เลื่อน C5, C4/C6 ส่วนที่พึ่ง full workload และ

F-11 คง Development Complete ไม่ใช่ Completed; ต้องตรวจรับครบก่อนใช้เงินจริง
หรือเปิดให้คนนอก และไม่อนุมัติ production PREPARED, commit/push/merge
หรือข้ามจุดอนุมัติ spec ของ feature ถัดไป.

## Amendment — ลบ MACD ทั้งระบบ (Approved 2026-10-13)

เจ้าของระบุให้ลบกลุ่ม MACD ทั้ง UI และ code รวม backend. Amendment นี้
ให้แทนทุกข้อที่ระบุชุด indicator เดิมด้วย EMA20/50/200, RSI14 และ ATR14 เท่านั้น;
เลิกคำนวณและส่ง `macd_line`, `macd_signal`, `macd_histogram` ในผล F-11 และ
สัญญาข้อมูลกราฟ F-12. ห้ามเปลี่ยนสูตร พารามิเตอร์ การปัด หรือสถานะของ indicator ที่เหลือ.

ข้อมูลผลลัพธ์และ checkpoint ที่สร้างด้วยชุดสูตรเดิมต้องไม่ถูกอ่านเป็นชุดสูตรใหม่หรือ
แสดงผลปนกัน. แผนต้องกำหนด formula/schema version, การรับมือข้อมูลที่เก็บไว้,
การเปลี่ยนผ่าน LEGACY/PREPARED และความเข้ากันได้ระหว่าง replica ก่อนแก้โค้ด;
ห้ามให้ cache/cursor/generation เก่าถูกตีความเป็นผลใหม่. ตรวจ regression ของค่า
indicator ที่เหลือ รวมถึง error/refresh/retry และการอ่านข้าม replica ตาม validation.
ไม่แตะกฎออเดอร์ เงิน ความเสี่ยง หรือเปิด Live Trading จากการลบนี้.

เจ้าของยืนยันให้เลื่อนการทดสอบโหลดและความเสถียรระยะยาวไปตรวจรับระบบรวม

## ทำไมต้องมี

กราฟและกลยุทธ์ต้องใช้ผล indicator จาก backend ชุดเดียวกันตาม
`tech-stack.md` หัวข้อ 3 ไม่คำนวณสูตรซ้ำที่ frontend
F-09 มีประวัติ OHLCV และรายงานช่วงที่ขาดแล้ว; F-10 มีราคาล่าสุดและสถานะ
แต่ราคาล่าสุดไม่ใช่แท่งเทียนและไม่ใช่หลักฐานว่าแท่งปิดแล้ว

NC-09 ปิดการเลือกชุดเริ่มต้นแล้ว: EMA20/50/200, RSI14, MACD12/26/9,
ATR14 บน timeframe 1m, 5m, 15m, 1h, 4h, 1d
การเลือกชื่อ indicator ไม่ได้อนุมัติสูตร seed หรือกฎซื้อขาย

## ขอบเขตที่เสนอ

คำนวณชุดเริ่มต้นจากประวัติแท่งเทียน F-09 ด้วยตรรกะบริสุทธิ์ใน core
และเปิดทางอ่านผลผ่าน API ที่ยืนยันตัวตน เพื่อให้งานกราฟ F-12 และงานกลยุทธ์
ใช้สัญญาผลลัพธ์เดียวกันได้ โดยยังไม่ implement กราฟหรือบอท
รองรับ 5 คู่ตั้งต้น BTCUSDT, ETHUSDT, SOLUSDT, XRPUSDT, DOGEUSDT
ไม่เพิ่มพารามิเตอร์ indicator ที่ผู้ใช้ปรับเองในงานนี้

ไม่ส่งออเดอร์ ไม่สร้าง buy/sell signal ไม่เปิด Live ไม่แตะยอดเงินหรือ position
ไม่เพิ่ม candle stream ไม่เปลี่ยน finality/retention ของ F-09
ไม่แก้สูตรหรือข้อกำหนดที่อนุมัติแล้วของ Money/Quantity

## ข้อเสนอที่ต้องให้เจ้าของตัดสินใจ

ทุกข้อด้านล่างได้รับอนุมัติเมื่อ 2026-10-10 ตามคำสั่ง “approve”

### NC-30 — Closed: สูตรและ warm-up

ข้อเสนอ:

- EMA(n) ใช้ close; seed ด้วยค่าเฉลี่ย n แท่งแรก แล้วใช้
  `EMA = previous EMA + 2/(n+1) × (close − previous EMA)`
  ค่าแรกอยู่ที่แท่ง n; ก่อนหน้านั้นไม่มีค่า
- RSI14 ใช้ผลต่าง close 14 ช่วง (15 แท่ง); seed average gain/loss
  ด้วยค่าเฉลี่ย 14 ช่วง แล้ว smoothing แบบ `(previous × 13 + current)/14`
  สูตร `100 − 100/(1 + average gain/average loss)`;
  loss เป็นศูนย์อย่างเดียวให้ 100, gain เป็นศูนย์อย่างเดียวให้ 0,
  ทั้งคู่เป็นศูนย์เสนอให้ 50
- MACD line = EMA12 − EMA26 โดย seed EMA แต่ละเส้นตามข้างต้น;
  signal = EMA9 ของ MACD line ที่มีค่าแล้ว; histogram = line − signal
  line เริ่มที่แท่ง 26; signal/histogram เริ่มที่แท่ง 34
- ATR14 ใช้ true range = ค่าสูงสุดของ high−low, |high−previous close|,
  |low−previous close|; เริ่มจากแท่งที่สองเพื่อมี previous close
  seed ด้วยค่าเฉลี่ย 14 true ranges (15 แท่ง) แล้ว smoothing แบบ RSI

NC-30 ปิดแล้ว: ใช้สูตรและเกณฑ์ตรวจผลข้างต้น
ข้อเสนอนี้ไม่รับรองว่าจะตรงกับค่าเริ่มต้นของ chart/library ภายนอก

### NC-31 — Closed: Finality และช่วงข้อมูลขาด

F-09 ระบุ REST candles เป็น UNCONFIRMED; ยังไม่มี closure proof
ถ้าอนุญาตเฉพาะ CLOSED จะยังคำนวณผลจากประวัติปัจจุบันไม่ได้

แก้ review ข้อ2 ตามคำสั่งเจ้าของ 2026-10-10: ข้อเสนอเกณฑ์รับแท่งเพื่อแสดงผล
ต้องตรวจทั้งเวลาของแท่งและเวลาที่เริ่มดึงข้อมูล OHLC ที่เก็บอยู่:

| ข้อมูลต้นทาง | ใช้คำนวณใน F-11 ได้หรือไม่ |
|---|---|
| `end_at > as_of` หรือสถานะ `OPEN` | ไม่ใช้ ไม่เพิ่มเข้า seed หรือ state ของ indicator |
| `end_at <= as_of`, `UNCONFIRMED` และ `fetch_started_at < end_at` หรือไม่มีหลักฐานเวลาที่เริ่มดึง | ไม่ใช้; รายงาน `REFRESH_REQUIRED` และไม่มีค่าผลที่พึ่งแท่งนี้ |
| `end_at <= as_of`, `UNCONFIRMED` และ `fetch_started_at >= end_at` | ใช้เพื่อแสดงผลได้ แต่ยังระบุ finality ว่ายืนยันไม่ได้ |
| `end_at <= as_of` และ `CLOSED` จากหลักฐานต้นทางตามสัญญา F-09 | ใช้ได้ตาม finality ที่ F-09 รับรอง ห้าม F-11 สร้างหลักฐาน CLOSED เอง |

`fetch_started_at` ต้องเป็นของการดึงที่ให้ค่า OHLC รุ่นนั้นและบันทึกสำเร็จแล้ว
ใช้ `StoredCandle` และความหมาย `refresh_due` ของ F-09 เป็นฐาน
เวลาที่ได้รับคำตอบ (`observed_at`), `last_checked_at`, เวลาที่อ่าน API
หรือเวลาปัจจุบัน ไม่ใช้แทนหลักฐานว่าคำขอเริ่มหลังจบช่วง
คำขอที่เริ่มก่อน end_at แต่ตอบกลับหลัง end_at ยังต้อง refresh

`REFRESH_REQUIRED` เป็นเหตุผลว่าข้อมูลยังใช้ไม่ได้ ไม่ได้ยืนยันว่ามีงาน refresh
อยู่ในคิว; แสดงสถานะคิว/ความล้มเหลวจาก F-09 ตามจริง การขอ refresh ใช้ทางเดิม
ของ F-09 โดยรายละเอียดการเชื่อมอยู่ในแผน ไม่ให้ indicator core/API เรียกตลาดเอง
แก้ deep review ข้อ5: แผนระบุผู้ใช้ผลเป็นผู้ขอ POST เดิม พร้อม target/queue metadata
ของ F-11, pollingที่จำกัด และการอ่าน indicatorชุดใหม่หลังrefresh; integration
consumerในvalidation V-17พิสูจน์ครบทาง โดยGET indicatorไม่enqueueเอง
เวลาผ่านไป การ enqueue หรือ refresh ล้มเหลว ไม่ทำให้แท่งนั้นผ่านเกณฑ์
ต้องมี OHLC จากการดึงใหม่ที่เข้าเกณฑ์และ commit สำเร็จก่อนคำนวณใหม่

ระหว่างที่แท่งต้อง refresh ห้ามนำค่ามาสะสม seed หรือเลื่อน recursive state
ผลของแท่งนั้นและผลถัดไปที่ต้องพึ่งแท่งนั้นในช่วงต่อเนื่องเดียวกันไม่มีค่า
และระบุ `REFRESH_REQUIRED`; ผลก่อนหน้าที่ยังไม่พึ่งแท่งนั้นอ่านได้ตามปกติ
ห้ามข้ามแท่งนี้ไปต่อ state หรือเริ่ม seed ใหม่เพื่อหลบการรอ refresh
แท่งที่มีข้อมูลแต่ต้อง refresh แยกจากช่องเวลาที่ไม่มีข้อมูลจริงตามกฎ gap ด้านล่าง

เมื่อคำนวณได้ ผลที่พึ่งแท่ง UNCONFIRMED ใดใน seed/state ยังต้องระบุว่า finality
ยืนยันไม่ได้ แม้แท่งปลายทางจะเป็น CLOSED; ไม่รับรองว่าพร้อมใช้ตัดสินใจเทรด
การดึงหลังจบช่วงเป็นเพียงเกณฑ์รับข้อมูลคำนวณ ไม่ได้ยกระดับ finality ของแท่ง
เมื่อขาดแท่ง ให้แยกเป็นช่วงต่อเนื่องและเริ่ม seed/warm-up ใหม่หลัง gap
ช่วงที่ยัง warm-up ไม่ครบไม่มีค่า ไม่เชื่อมช่วงด้วยแท่งจำลอง

เกณฑ์ตรวจข้อ2 (เป็นส่วนหนึ่งของ RQ-13):

- แท่ง 10:00–10:01 ที่เริ่มดึง 10:00:30 ยังเป็น `REFRESH_REQUIRED` เมื่ออ่าน
  ตอน 10:02 แม้คำตอบจะมาถึงหลัง 10:01 หรือมีการขอ refresh แล้ว
- ขอบ `fetch_started_at = end_at` ผ่านเกณฑ์เวลาสำหรับ UNCONFIRMED;
  ก่อนขอบแม้เพียงหนึ่ง microsecond ยังไม่ผ่าน และห้ามใช้แท่งที่ `end_at > as_of`
- refresh ล้มเหลวหรือยังไม่ commit ต้องไม่มีค่าผลที่พึ่งแท่งนั้น; หลัง commit
  ข้อมูลที่เข้าเกณฑ์จึงคำนวณใหม่ได้ และยังคงสถานะ UNCONFIRMED
- พิสูจน์ว่าแท่งที่ต้อง refresh ไม่ปนใน seed/state ไม่ถูกข้ามไปคำนวณแท่งถัดไป
  และไม่กระทบผลก่อนหน้า; CLOSED ที่ตามหลัง seed แบบ UNCONFIRMED
  ต้องไม่ทำให้ผล indicator ถูกอ้างว่าใช้ข้อมูลยืนยันแล้วทั้งหมด

NC-31 ปิดแล้ว: อนุมัติขอบเขต input สถานะผลและกฎ reset หลัง gap ข้างต้น
กฎการใช้ผลกับบอทต้องอนุมัติในงานกลยุทธ์ภายหลัง

### NC-32 — Closed: จุดเริ่ม seed และการเปลี่ยนประวัติ

EMA/RSI/MACD/ATR มี state จากอดีต; เปลี่ยนจุดเริ่มคำนวณย่อมเปลี่ยนผล
การอ่านต่างหน้า การ backfill และขอบเก็บ 365 วันจึงต้องมี semantics ที่ตกลงก่อน

แก้ review ข้อ1 ตามคำสั่งเจ้าของ 2026-10-10: ให้ backend กำหนดชุดคำนวณกลาง
ต่อแหล่งข้อมูล/คู่/timeframe/รุ่นสูตร/รุ่นข้อมูล แล้วให้กราฟและบอทอ้างอิงชุดเดียวกัน
ผู้เรียกระบุได้เฉพาะช่วงผลที่ต้องการอ่าน ไม่เลือกจุดเริ่ม seed หรือจำนวนแท่ง
warm-up เอง; การซูมกราฟ เปลี่ยนจำนวนจุด หรือแบ่งหน้าเป็นการเลือกผลจากชุดกลาง
ไม่ใช่การเริ่มคำนวณใหม่จากแท่งแรกที่ผู้เรียกขอ

ในชุดข้อมูลกลางแต่ละรุ่น เสนอให้ใช้แท่งแรกที่เข้าเกณฑ์ของแต่ละช่วงต่อเนื่อง
เป็นจุดเริ่มสะสม seed ตามสูตร NC-30 และกฎ gap NC-31
จุดเริ่มนี้เป็นส่วนหนึ่งของตัวตนชุดคำนวณและคงที่ตลอดรุ่นข้อมูลนั้น
ต้องพิจารณาประวัติก่อนช่วงแสดงผลด้วย แม้ผู้เรียกขอเพียงแท่งเดียว
หากข้อมูลต้นทางไม่พอ ต้องรายงาน warm-up ตามชุดกลาง ไม่เริ่ม seed ใหม่
ให้พอดีกับขอบคำขอ

เกณฑ์ตรวจข้อ1: เมื่อกราฟขอ 200 จุดและบอทขอ 1,000 จุดจากชุดกลางเดียวกัน
ค่า indicator และสถานะ warm-up ของทุกแท่งที่ทับซ้อนกันต้องตรงกันทุกค่า
การแบ่งคำขอเดิมเป็นหลายหน้าหรือเปลี่ยนช่วงแสดงผลต้องให้ผลเดียวกันด้วย
ทดสอบผู้ใช้ผลผ่านสัญญา backend ได้โดยไม่ต้องสร้างกราฟหรือบอทใน F-11

ประวัติที่ยังไม่ครบให้รายงานตามจริง ไม่รับรองว่ามี 365 วันเต็ม
เมื่อ backfill/แก้ข้อมูลทำให้ input ต่างไป อนุญาตคำนวณใหม่และรายงานตัวตน
ของชุดข้อมูลที่ใช้; ไม่รับรองว่าเลขเดิมคงอยู่หลัง input เปลี่ยน

แก้ review ข้อ3 ตามคำสั่งเจ้าของ 2026-10-10: เสนอให้ปฏิเสธการอ่านต่อ
เมื่อชุดข้อมูลเปลี่ยนและให้เริ่มอ่านใหม่ โดยมีสัญญาดังนี้:

1. หน้าแรกระบุตัวตนชุดคำนวณ รุ่นข้อมูล รุ่นสูตร จุดเริ่ม seed ของช่วงต่อเนื่อง
   ขอบเขตผลที่ขอ และ `as_of` ที่ backend กำหนด พร้อมตัวอ้างอิงสำหรับอ่านต่อ
   หน้าถัดไปต้องผูกกับค่าเหล่านี้และตำแหน่งที่อ่านถึง ไม่เลือกชุดใหม่จากเวลาปัจจุบัน
   และไม่อนุญาตสลับคู่/timeframe/ขอบเขตผลในตัวอ้างอิงเดิม
2. รุ่นข้อมูลต้องครอบคลุมประวัติที่ใช้สะสม seed/state ก่อนหน้าแรกด้วย
   รวมข้อมูลแท่ง การมี/ขาดของแท่ง finality และหลักฐานรับแท่งตาม NC-31
   การ backfill, แก้ OHLC, refresh ที่เปลี่ยนสิทธิ์การใช้แท่ง หรือ retention
   ที่ทำให้หลักฐาน/จุดเริ่ม seed ของชุดเดิมใช้ไม่ได้ ต้องทำให้การอ่านต่อชุดเดิมใช้ไม่ได้
   แม้แท่งที่เปลี่ยนจะอยู่นอกหน้าที่กำลังขอหรือผลตัวเลขบังเอิญเท่าเดิม
3. แต่ละหน้าต้องอ่านข้อมูลและคำนวณจากภาพข้อมูลที่สอดคล้องกันกับรุ่นที่อ้าง
   การตรวจรุ่นแล้วปล่อยให้ข้อมูลเปลี่ยนก่อนอ่านหรือระหว่างคำนวณจนเกิดผลปนรุ่น
   ถือว่าไม่ผ่าน; ถ้าพิสูจน์ความสอดคล้องไม่ได้ต้องปฏิเสธหน้า ไม่ส่งผลบางส่วน
4. เมื่อรุ่นไม่ตรง ชุดเดิมหมดอายุ หรือหลักฐานชุดเดิมถูกลบ ให้คืน
   `HTTP 409` พร้อมรหัส `INDICATOR_DATASET_CHANGED` และไม่มีแถว indicator
   ห้าม fallback ไปใช้ seed/ข้อมูลรุ่นล่าสุดภายใต้ตัวอ้างอิงเก่า
   ตัวอ้างอิงผิดรูปหรือถูกดัดแปลงต้องถูกปฏิเสธตามกฎตรวจ input เดิม
5. ผู้ใช้ผลทั้งกราฟและบอทต้องทิ้งหน้าที่สะสมของการอ่านที่ถูกปฏิเสธแล้วเริ่มจากหน้าแรก
   ห้ามนำหน้าชุดใหม่มาต่อกับหน้าชุดเก่า; การ retry เริ่มใหม่ต้องมีขอบเขต
   ไม่วนจนสำเร็จโดยไม่มีเพดาน รายละเอียดเพดานและตัวอ้างอิงกำหนดในแผน
6. แท่งใหม่ที่อยู่นอกขอบเขตคำนวณที่ตรึงไว้ ไม่ถูกเพิ่มเข้าการอ่านชุดเดิม
   การอ่านข้อมูลล่าสุดเป็นการเริ่มคำขอชุดใหม่ การมีแท่งใหม่นอกขอบเขตเพียงอย่างเดียว
   ไม่ควรทำให้การอ่านเดิมต้องเริ่มใหม่ หาก input/seed/สถานะของชุดเดิมยังคงเดิม

เกณฑ์ตรวจข้อ3 (เป็นส่วนหนึ่งของ RQ-13):

- อ่านหลายหน้าโดยข้อมูลไม่เปลี่ยนต้องได้ผลเท่ากับอ่านชุดเดียว และไม่มีแท่งซ้ำ/ตกหล่น

  ที่ชุดเดิมต้องใช้: ต้องปฏิเสธการอ่านต่อ แม้ค่าของหน้าถัดไปอาจดูเหมือนเดิม

### NC-33 — Closed: ความละเอียดและค่าที่ไม่มีหน่วย

Money เดิมมีขอบความละเอียดและบังคับให้ระบุการปัดเมื่อคูณแล้วเก็บไม่ลง
สูตร indicator ต้องหารด้วยจำนวนช่วง/อัตราและ RSI ไม่มีหน่วยเงิน
ยังไม่มีสัญญา indicator numeric type ใน repo

ข้อเสนอ numeric contract หลังแก้ deep review ข้อ1 (2026-10-10):
รายละเอียดด้านล่างได้รับอนุมัติและปิด NC-33 เมื่อ 2026-10-10

### ชนิดและความละเอียด

- ราคา, EMA, MACD line/signal/histogram, true range, ATR และค่าเฉลี่ย gain/loss
  ใช้ `Money` สกุล quote เดียวกับแท่ง; volume คงเป็น `Quantity` และไม่เข้าสูตรชุดนี้
- เสนอเพิ่ม `Scalar` ที่ไม่มีหน่วยใน `core.money` สำหรับ RSI เท่านั้นใน F-11
  ใช้ validation, context, ขอบช่วงและรูปแบบข้อความเดิมของ F-02;
  ห้ามใช้สกุลเงิน/ชื่อเหรียญสมมติแทนค่าที่ไม่มีหน่วย
- ค่า public และ state ทุกจุดใช้ `STORED_SCALE` เดิม (18 ตำแหน่ง),
  ค่าสัมบูรณ์น้อยกว่า `MAX_ABS` เดิม (10^20); คำนวณภายในโมดูล money
  ภายใต้ `COMPUTE_PRECISION` เดิม (80 หลัก) ทุกครั้ง
- RSI ต้องอยู่ใน [0,100], ATR/gain/loss ไม่ติดลบ; ถ้าผลผิด invariant ให้ error
  ห้าม clamp ผลกลับเข้าช่วง ส่วน MACD รับค่าลบได้ตาม Money เดิม

### Operation ที่ต้องเพิ่ม โดยไม่เปลี่ยนพฤติกรรมของของเดิม

เสนอเพิ่ม public operations ใน `core.money` ซึ่งรับ/คืนชนิดข้อมูลกลางเท่านั้น:

| Operation | สัญญา |
|---|---|
| `divide_money(value, divisor, *, rounding)` | Money หารจำนวนเต็มบวก 1..200; คืน Money หน่วยเดิม ปัดครั้งเดียวที่ผลหาร |
| `weighted_mean_money(terms, *, rounding)` | 1..200 terms ของ Money หน่วยเดียวกันกับน้ำหนักจำนวนเต็มบวก; น้ำหนักรวมไม่เกิน 201; รวม numerator แบบ exact แล้วหารน้ำหนักรวม ปัดครั้งเดียวที่ผลสุดท้าย |
| `percentage_share(part, other, *, rounding)` | Money สกุลเดียวกัน ไม่ติดลบและผลรวมมากกว่าศูนย์; คืน Scalar จาก `100 × part / (part + other)` ปัดครั้งเดียวที่ผลสุดท้าย |

reject bool แทน int, น้ำหนัก/ตัวหารผิดขอบ, unit mismatch, nonfinite และ input
ผิดชนิดด้วย typed errors ตามกลุ่มเดิมของ money ก่อนคำนวณ ไม่กำหนดค่า rounding ปริยาย
การบวกคูณ numerator ภายใน operation อาจเกินช่วง Money ได้ชั่วคราว
แต่ไม่สร้าง Money/Scalar จากค่านั้น; ใช้ขอบคำนวณ 80 หลัก และตรวจผล exact
ก่อนปัดว่าล้นช่วง public หรือไม่ ผลล้นช่วงต้อง error ห้ามปัดให้กลับเข้าช่วง
ข้อนี้ไม่อนุญาตให้บวก/คูณ Money แบบ public ข้าม invariant เดิม

### จุดและทิศทางการปัดของ indicator รุ่นแรก

เสนอให้ทุก operation ใหม่ที่ F-11 เรียกระบุ `RoundingDirection.TOWARD_NEGATIVE`
อย่างชัดเจน ปัดเข้าหาค่าลบที่ 18 ตำแหน่ง; ไม่เพิ่ม rounding mode ใหม่
นี่เป็นนโยบายตัวเลขสำหรับ indicator ที่ต้องอนุมัติ ไม่อ้างว่าปลอดภัยต่อทุกกลยุทธ์
หรือเป็นทิศทางที่ไม่เข้าข้างผู้ใช้สำหรับการเทรดทุกประเภท

| ขั้นตอน | ลำดับคำนวณที่กำหนด |
|---|---|
| seed ของ EMA/RSI averages/ATR | weighted mean ด้วยน้ำหนัก 1 ทุกค่า; ปัดครั้งเดียวเมื่อได้ค่าเฉลี่ย |
| EMA(n) และ MACD signal EMA9 | weighted mean ของ previous ด้วยน้ำหนัก n−1 และ input ด้วยน้ำหนัก 2; ปัดครั้งเดียว ห้ามสร้าง alpha ที่ปัดก่อนนำไปคูณ |
| RSI average gain/loss และ ATR smoothing | weighted mean ของ previous ด้วยน้ำหนัก 13 และ current ด้วยน้ำหนัก 1; ปัดครั้งเดียว |
| MACD line/histogram, close delta และ true range | บวก/ลบ/เทียบ Money ที่อยู่ในช่วงเดิม แบบ exact ไม่เพิ่มจุดปัด |
| RSI เมื่อ gain/loss ไม่เป็นศูนย์ทั้งคู่ | ใช้ percentage_share(gain, loss); ไม่สร้าง RS ที่ปัดแล้วค่อยหารซ้ำ |
| RSI เมื่อ loss=0 หรือ gain=0 | คืน Scalar 100 หรือ 0 ตาม NC-30; เมื่อทั้งคู่=0 เสนอ 50 ตาม NC-30 ไม่เรียก operation หาร |

ค่าที่ปัดแล้วเป็น state สำหรับแท่งถัดไปและเป็นค่าที่ส่งออก ไม่มี state ลับ
ละเอียดกว่าค่าที่เปิดเผย; ไม่ปัดซ้ำก่อนส่ง API และไม่ปัดตาม tick size ตลาด
สูตรแบบ weighted mean และ percentage share เทียบเท่าสูตร NC-30 ก่อนปัด
แต่ลำดับการปัดข้างต้นเป็นส่วนหนึ่งของรุ่นสูตร ห้ามสลับรูปนิพจน์เอง

การปัดผล exact หนึ่งครั้งมี error อยู่ใน `(-10^-18, 0]`;
ขอบนี้ใช้กับ operation เดียว ไม่ใช่การรับรอง error รวมของ recursive series
ตัวเลขทั่วไปที่ไม่สิ้นสุดจึงส่งเป็นข้อความของค่าที่ปัดตามสัญญา ไม่ใช่คำอ้างว่า
แทนค่าทางคณิตศาสตร์ได้ครบทุกหลัก

### ตัวอย่างอ้างอิงและข้อผิดพลาด

| Input/ขั้นตอน | Expected ตามข้อเสนอ |
|---|---|
| Money 1 USDT หาร 3 | `0.333333333333333333` USDT |
| Money −1 USDT หาร 3 | `-0.333333333333333334` USDT |
| ค่าเฉลี่ย Money 1, 2, 2 USDT | `1.666666666666666666` USDT |
| EMA20: previous=100, close=101 | `100.095238095238095238` USDT จาก 2102/21 |
| RSI average gain=1, loss=2 | Scalar `33.333333333333333333` จาก 100/3 |
| ค่าเฉลี่ยของ Money 9×10^19 สองค่า | `90000000000000000000` USDT แม้ numerator ชั่วคราวเกิน MAX_ABS |
| MACD histogram: line=9×10^19, signal=−9×10^19 | typed OutOfRangeError จากผล 1.8×10^20; ไม่ clamp |
| positive 10^-18 หาร 3 | `0`; ต้องนับกรณีนี้ในเทสต์ RSI เพื่อพิสูจน์กฎ zero branch จาก state ที่ปัดแล้ว |

typed numeric failure ยุติคำขอทั้งหน้า ไม่มี partial success, ไม่มีค่าเก่ามาแทน
API คืน `422 / INDICATOR_NUMERIC_ERROR` แบบไม่มี input/secret/stack trace
ไม่ใช้ 409 เพราะ numeric error ไม่ใช่หลักฐานว่ารุ่นข้อมูลเปลี่ยน
การลอง input/รุ่นเดิมใหม่ต้องได้ error เดิม ไม่ retry งานคำนวณอัตโนมัติ

ข้อเสนอขยาย `core.money` เฉพาะ operations/Scalar นี้ต้องอนุมัติพร้อม NC-33
ไม่แก้พฤติกรรม existing Money/Quantity, ไม่เปลี่ยน scale/range/context เดิม
และไม่อนุญาต raw financial Decimal นอกโมดูล money

NC-33 ปิดแล้ว: อนุมัติ numeric contract และส่วนขยาย core.money ข้างต้น

## กฎความปลอดภัยที่เกี่ยวข้อง

คงกฎ trading-safety หัวข้อ 2/5/6/13: ไม่อ่าน secret ไม่ส่งออเดอร์

ไม่เพิ่มกฎเทรดจากค่าหรือชื่อ indicator และไม่เปิด Live โดยปริยาย
