## คำตัดสินของเจ้าของ

ยกเลิกการรองรับ sub-account และหลายกระเป๋าในโค้ดและแผน
ยังเป็นระบบหลายผู้ใช้ แต่ผู้ใช้หนึ่งคนใช้บัญชี Binance TH ของตนเองเพียงบัญชีเดียว
เลือกใช้เทรดมือหรือบอททีละแบบ ไม่ใช้พร้อมกัน คำตอบเจ้าของ 2026-10-07
แทน R-13 และ F-08 ฉบับหลายกระเป๋าที่อนุมัติก่อนหน้า

เหตุผลด้านการใช้งานที่เจ้าของแจ้ง: ในขั้นตอนสร้าง sub-account ที่เจ้าของพบ
ต้องเตรียมอีเมลและเบอร์โทรที่ไม่ซ้ำกับบัญชีหลักและบัญชีย่อยอื่น ทำให้การตั้งค่า
หลายบัญชีมีภาระเพิ่ม จึงเลือกใช้บัญชีเดิมหนึ่งบัญชีต่อผู้ใช้
ข้อความนี้บันทึกประสบการณ์ของเจ้าของ ไม่ใช่การรับรองนโยบายของตลาดทุกวิธีสร้างบัญชี

## ขอบเขต

ยกเลิกทะเบียนหลายกระเป๋า การเลือก/สร้างกระเป๋า การผูก key แยกต่อกระเป๋า
เพดาน6กระเป๋าและการใช้ UID เพื่อแยกบัญชี ไม่เพิ่มคำสั่งสร้าง/จัดการ/โอนระหว่าง sub-account
คง TailAdmin account UI, การยืนยันตัวตน/TOTP และการตรวจ key ของ F-07
ยังไม่เพิ่มออเดอร์ บอทที่รันได้ ยอดเงิน หรือเปิด Live

Subscription แบบชำระเงินแยกต่อบัญชีผู้ใช้ TiewTrade ตามคำตัดสินใน mission หัวข้อ5
การชำระเงิน/แพ็กเกจ/สิทธิ์สมาชิกต้องมี spec ของงานนั้นเอง ไม่เพิ่ม billing ใน F-08

|---|---|
| RQ-1 | หนึ่งบัญชีตลาดต่อผู้ใช้หนึ่งคน ไม่ใช้บัญชีตลาดร่วมกันทั้งระบบ; ข้อมูลของผู้ใช้ต้องแยกด้วย auth/RLS เดิม |
| RQ-2 | เก็บ API key ได้หนึ่งชุดต่อผู้ใช้ รวมทุกสถานะ ต้องลบชุดเดิมก่อนเพิ่มใหม่; บังคับทั้ง API/storage และ DB ไม่เพียงหน้าเว็บ |
| RQ-3 | ใช้ key ของบัญชีที่ผู้ใช้เตรียมเอง; การตรวจผ่านหมายถึง credential ใช้งานได้ ไม่ใช่หลักฐาน UID/สิทธิ์ตลาด; ไม่สร้างบัญชีตลาดให้ |
| RQ-4 | เลือก MANUAL หรือ BOT ได้อย่างเดียว เก็บความเลือกที่ server; ก่อนเลือกเป็น null ไม่เปิดวิธีใดให้โดยปริยาย |
| RQ-5 | การเลือกครั้งแรกต้องมี key ACTIVE ของตนและ fresh TOTP ไม่รับ recovery/grace; การเลือกไม่ทำให้เทรดหรือรันบอทได้ |
| RQ-6 | เปลี่ยน MANUAL/BOT ได้เมื่อพิสูจน์ว่าไม่มีบอททำงาน ออเดอร์ค้าง หรือ position ที่ระบบดูแล; ยังไม่มีหลักฐานครบให้ปฏิเสธ ไม่ถือว่าข้อมูลที่ไม่มีคือ idle |
| RQ-7 | คงสูงสุด1บอทต่อบัญชีในงานบอทภายหลัง; F-08 นี้ไม่รันบอท |
| RQ-8 | เลิก wallet registry/routes/DTO/UI/digest/6-wallet quota และ wallet binding/disconnect audit ใน implementation เดิม; ไม่ลบประวัติ audit/ข้อมูลที่มีอยู่โดยอัตโนมัติ |
| RQ-9 | คง TailAdmin shell/components และ account-scoped QueryClient; API key และความเลือก MANUAL/BOT ไม่รั่วข้ามผู้ใช้ รวม late GET/POST completions |
| RQ-10 | ไม่แสดงยอด ไม่เพิ่ม balance WebSocket ไม่ส่งออเดอร์หรือเปิด Live; Paper/Live ที่มีในอนาคตยังต้องแยกและเป็น immutable ตามมาตรฐาน |
| RQ-11 | key/secret ไม่ออก API/error/log/audit/cache/storage; แสดงเฉพาะ4หลักท้าย; ถอด secret เฉพาะ engine และใช้กุญแจเดิมของ F-07 |
| RQ-12 | การเลือกประเภทมี audit UUIDของผู้ใช้กับค่าMANUAL/BOTเท่านั้น และ transaction เดียวกับการเขียน; audit ล้มเหลวต้อง rollback |
| RQ-13 | ไม่เพิ่ม endpoint ถอน/โอน/จัดการบัญชีย่อย; safety gates ที่ห้าม endpoint เหล่านี้คงอยู่ แม้เลิกฟีเจอร์ sub-account |
| RQ-14 | ถ้าข้อมูลเดิมมีหลาย key ต่อผู้ใช้ migrationต้องปฏิเสธ ไม่เลือกหรือลบ key ให้; ถ้ามี migration0012เดิมใช้แล้วต้องหยุดวางแผนรักษาข้อมูลก่อนเปลี่ยนไฟล์ |
| RQ-15 | การอนุญาตใช้บัญชีหรือเปลี่ยน credential เมื่อมีการเทรดจริง ต้องมีเกณฑ์จากงาน orders/positions/Live ภายหลัง; F-08ไม่อ้างว่าพร้อมเทรดจากความเลือกหรือ key ACTIVE |
| RQ-16 | หยุดบอทไม่เปลี่ยนประเภท BOT เป็น MANUAL และไม่อนุญาต manual opening ในประเภท BOT; การปิด/ลด position และยกเลิกออเดอร์ทำได้ทุกประเภทตาม trading-safety หัวข้อ3/8; การเปลี่ยนประเภทใช้ RQ-6 |

การมีหนึ่ง key ในระบบบังคับให้เชื่อมหนึ่งบัญชีในเวลาหนึ่ง ไม่พิสูจน์บัญชีจริง/UID
หรือรับรองว่า key ที่เพิ่มภายหลังเป็นบัญชีเดิม ต้องระบุข้อจำกัดนี้ในเอกสาร ไม่เดาจากยอด

## Review issue 1 — การแยกฐานข้อมูล E2E (อนุมัติเฉพาะการแก้นี้)

เจ้าของสั่งแก้ issue 1 วันที่ 2026-10-07: ก่อนล้าง auth_throttle ต้องระบุฐานข้อมูล
E2E ที่ทิ้งได้อย่างชัดเจน ปฏิเสธฐานข้อมูลทั่วไป/remote/URL ข้ามฐานหรือข้าม server
API, AUTH, engine และ migrator ต้องชี้ฐานเดียวกัน; ตรวจ current_database() ก่อน DELETE
ห้าม reuse server ที่เปิดอยู่และห้ามแสดง URL/password จาก validation หรือ subprocess error
คำสั่งนี้อนุมัติเฉพาะ security repair ของ E2E ไม่อนุมัติรายละเอียดบัญชีเดียวทั้งฉบับ
