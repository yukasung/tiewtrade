# Standard — Backend

สถานะ: **Proposed** — ภาษาและ framework ตัดสินแล้ว: **Python + FastAPI** (T-01, T-07 ปิด 2026-09-26)

---

## 1. เงิน

- **ใช้ `Decimal` เสมอ ห้ามใช้ `float` ที่ไหนก็ตามที่เกี่ยวกับเงิน ราคา จำนวน หรืออัตรา**
- ตั้งค่าความละเอียดของการคำนวณไว้ที่เดียวและใช้ร่วมกันทั้งระบบ ไม่ใช่ปล่อยตามค่าเริ่มต้น
  ของแต่ละที่ — ไม่เช่นนั้นผลลัพธ์จะต่างกันตามว่าใครเรียก
- การปัดเศษต้องตั้งใจและระบุชัดทุกครั้ง ห้ามปล่อยให้ปัดเอง
- **เมื่อต้องปัด ให้ปัดในทางที่ไม่เข้าข้างผู้ใช้** เพื่อไม่ให้ระบบแสดงผลดีเกินจริง
- ห้ามแปลงเงินเป็น `float` แม้แต่ตอนส่งออกทาง API — ส่งเป็นข้อความ

## 2. ชื่อ

- ใช้คำเดียวกับที่ใช้ใน spec ทั้งในโค้ด ฐานข้อมูล API และ UI
- ค่าคงที่แบบ enum เขียนเป็น `UPPER_SNAKE_CASE`
- ใช้คำศัพท์เทรดภาษาอังกฤษในโค้ดเสมอ แม้ UI จะเป็นภาษาไทย

## 3. ขอบเขตของโมดูล

- โค้ดที่คำนวณอยู่ใน `core` เท่านั้น service เป็นแค่ตัวประกอบและต่อโลกภายนอก
- ชนิดข้อมูลที่แทนค่าต่าง ๆ ควรสร้างแล้วแก้ไม่ได้ และตรวจความถูกต้องตั้งแต่ตอนสร้าง
- ระบุให้ชัดว่าอะไรคือของสาธารณะของโมดูล อะไรเป็นของภายใน

## 4. การจัดการข้อผิดพลาด

- ข้อผิดพลาดที่คาดไว้ได้ ต้องเป็นชนิดข้อมูลที่ระบุได้ ไม่ใช่ข้อความอิสระ
- ข้อความ error ที่ส่งไปหน้าบ้านต้องเป็นรหัส เพื่อให้แปลเป็นไทย/อังกฤษได้ (R-20)
- **ห้ามกลืน exception เงียบ ๆ** ถ้าจับแล้วไม่ทำอะไรต่อ ต้องเขียนเหตุผลกำกับ
- ข้อความ error ต้องไม่มี secret, API key หรือรหัสผ่าน

## 5. ห้ามเขียนซ้ำ

- ก่อนเขียนฟังก์ชันใหม่ ให้ค้นก่อนว่ามีของเดิมอยู่แล้วหรือไม่
- ถ้าตรรกะเดียวกันโผล่ครั้งที่สาม ให้ย้ายไปไว้ที่เดียว
- **ห้ามคัดลอกสูตรจากเอกสาร spec มาใส่เป็นคอมเมนต์** ให้อ้างถึงหัวข้อแทน
  เพราะสำเนาจะเก่าโดยไม่มีใครรู้
