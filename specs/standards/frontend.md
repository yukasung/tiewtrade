# Standard — Frontend

สถานะ: **Proposed**

---

## 1. ความปลอดภัยมาก่อนความสวย

- **ต้องเห็นตลอดเวลาว่ากำลังอยู่โหมด Paper หรือ Live** ไม่ใช่ซ่อนอยู่ในเมนู
  และสองโหมดต้องดูต่างกันชัดเจนจนมองแวบเดียวก็รู้
- ทุกการกระทำที่ใช้เงินจริงต้องมีขั้นยืนยัน ที่แสดงให้เห็นว่าจะเกิดอะไรขึ้นจริง ๆ
- ปุ่มหยุดบอทต้องกดถึงได้จากทุกหน้าจอ
- ห้ามแสดง API secret ไม่ว่ากรณีใด แสดงได้แค่ 4 หลักท้าย

## 2. การใช้ component ซ้ำ

การใช้ฟอร์มเทรดร่วมกันแต่แยกหน้า/URL ของ Paper และ Live ให้ยึด
[ADR-004](../decisions/004-shared-paper-live-trading.md) ที่เจ้าของยืนยัน 2026-10-15
รายละเอียด route และ component ต้องอยู่ใน spec ของ feature ก่อน implementation

- ตัวเลขเงิน วันเวลา และสถานะออเดอร์ ต้องแสดงผ่าน component กลางเสมอ
  เพื่อให้รูปแบบเหมือนกันทุกหน้า
- ก่อนสร้าง component ใหม่ ให้ค้นของเดิมก่อน
- สี ระยะห่าง และตัวอักษร มาจากชุดค่ากลาง ห้ามใส่ค่าดิบในแต่ละที่
- control แบบมาตรฐานทุกหน้า เช่น input, select/dropdown, label และ button ต้องใช้
  component กลางใน `frontend/src/components/ui/` ที่ปรับจาก `references/admin-template/`;
  ห้ามสร้าง style หรือเขียน native control ซ้ำในแต่ละหน้า ยกเว้น control เฉพาะทางของ layout
  ที่ admin template ใช้ native element โดยตรง เช่น backdrop หรือ sidebar toggle

### 2.1 Admin template เป็น UI source of truth

- ก่อนสร้างหรือแก้ UI ให้ค้น `references/admin-template/` ด้วยชื่อ component และหน้าที่ใช้งานก่อนทุกครั้ง
  แล้วบันทึก path ของต้นแบบใน comment ของ shared component หรือใน `plan.md`
- ต้องใช้โครงสร้าง component, design token และ interaction pattern จากต้นแบบ รวมถึง layout, สี,
  typography, spacing, width/height, border, radius, shadow, icon และ responsive breakpoint
- ต้องตรวจสถานะที่เกี่ยวข้องให้ตรงกับต้นแบบครบ: default, hover, focus, focus-visible, active,
  disabled, loading, error และ responsive ห้ามตรวจเฉพาะภาพเริ่มต้น
- ห้ามใช้ค่าสีหรือระยะ hard-coded, user-agent style หรือ CSS เฉพาะหน้ามาทับ shared component
  เพื่อสร้าง appearance ใหม่ เมื่อ admin template มี component หรือ token สำหรับกรณีนั้นแล้ว
- ถ้าต้นแบบมี component อยู่แล้วแต่โปรเจกต์ยังไม่มี ให้สร้างหรือขยาย shared component ใน
  `frontend/src/components/ui/` จากต้นแบบก่อน แล้วให้หน้าต่าง ๆ เรียกใช้ shared component นั้น
- การตรวจ UI ระหว่างพัฒนาให้ใช้ targeted component test และ browser smoke ของ state ที่เปลี่ยน
  โดยตรวจ computed style เมื่อความต่างของสี, border, focus ring หรือ responsive มองจาก assertion ปกติไม่ได้
- spec ที่อนุมัติแล้ว, accessibility และ trading safety มีลำดับเหนือ appearance ของ template;
  เมื่อจำเป็นต้องต่างจาก template ต้องระบุข้อกำหนดและเหตุผลของข้อยกเว้นไว้ชัดเจน ห้ามตัดสินใจต่างเอง

## 3. ข้อมูล

- ข้อมูลจาก server จัดการด้วย TanStack Query — **ห้ามเก็บซ้ำไว้ใน state ของหน้าจอ**
- state ในเครื่องเก็บเฉพาะสิ่งที่ไม่ได้มาจาก server (เช่น แท็บที่เลือกอยู่)
- **ห้ามคำนวณเงินที่หน้าบ้าน** ตัวเลขทุกตัวมาจาก backend เพราะถ้าคิดสองที่จะไม่ตรงกัน
- ค่า indicator บนกราฟก็มาจาก backend ด้วยเหตุผลเดียวกัน — บอทกับกราฟต้องเห็นเลขเดียวกัน

## 4. เรียลไทม์

- ต้องบอกผู้ใช้เสมอเมื่อการเชื่อมต่อหลุด — ห้ามแสดงข้อมูลเก่าเหมือนว่ายังสด
- ราคาที่เก่าเกินกำหนดต้องแสดงว่าเก่า ไม่ใช่แสดงเฉย ๆ
- **ข้อมูลบัญชี** (เงิน, ออเดอร์ค้าง, position) ต้องแสดงว่าเป็นของเมื่อไหร่
  และบอกเมื่อกำลังกระทบยอด ห้ามแสดงตัวเลขเฉย ๆ เหมือนทุกอย่างปกติ
  (`trading-safety.md` หัวข้อ 12)

## 5. หน้าจอที่กฎความปลอดภัยบังคับ

ข้อกำหนดเหล่านี้มาจากกฎใน `trading-safety.md` ที่ตัดสินเมื่อ 2026-09-26
ถ้าหน้าจอไม่ทำตามนี้ กฎเหล่านั้นจะไม่มีผลจริง

| ต้องมี | มาจาก |
|---|---|
| ปุ่มหยุดบอทแสดง **3 สถานะ** — กำลังหยุด / หยุดแล้วครบ / หยุดแล้วแต่มี n ใบยกเลิกไม่สำเร็จ **ห้ามแสดงว่าหยุดครบจนกว่าทุกใบจะรู้ผล** | หัวข้อ 8 |
| แสดงรายการออเดอร์ที่ถูกยกเลิกตอนกดหยุด ไม่ยกเลิกเงียบ ๆ | หัวข้อ 8 |
| หน้าสรุปก่อนกดเปิดบอทกลับ — ไม้ที่เปิดค้าง, ออเดอร์ที่ถูกยกเลิก, ออเดอร์ที่ยกเลิกไม่สำเร็จ **หน้านี้คือสิ่งที่กันการเปิดพลาด** | หัวข้อ 8 |
| เครื่องหมายบนไม้ที่ตั้ง TP/SL ไม่สำเร็จ ว่า **ไม่มีการป้องกัน** | หัวข้อ 11 |
| แยกสถานะ **"ส่งคำสั่งแล้ว"** ออกจาก **"ปิดเรียบร้อย"** ห้ามแสดงว่าปิดแล้วก่อน Binance ยืนยัน | หัวข้อ 6 |
| ช่องกรอกเพดานขาดทุน **เว้นว่างไม่ได้** ก่อนเปิด Live และแสดงยอดที่ใช้ไปเทียบเพดาน | หัวข้อ 13 |
| แสดงเหตุผลจริงจาก Binance เมื่อออเดอร์ถูกปฏิเสธ | หัวข้อ 12, 13 |

## 6. ภาษา
- **ห้ามเขียนข้อความลงในโค้ดโดยตรง** ทุกข้อความผ่านระบบแปล (R-20)
- ตัวเลข วันที่ และสกุลเงิน จัดรูปตามภาษาที่เลือก
- ศัพท์เทรดคงภาษาอังกฤษไว้แม้ในโหมดภาษาไทย เพื่อไม่ให้สับสนกับที่เห็นบน Binance
