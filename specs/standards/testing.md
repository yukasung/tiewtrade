## 1. ต้องเขียวก่อน merge

ด่านก่อน merge ต้องผ่านครบ ไม่อนุญาตข้าม lint/type/architecture/CI หรือเทสต์ความถูกต้อง
ความปลอดภัย การคำนวณเงิน และ regression ที่เกี่ยวข้อง

**การแบ่งด่านที่เจ้าของอนุมัติ 2026-10-11:** อนุญาต merge เพื่อพัฒนาต่อได้เมื่อ
implementation/review และด่านที่ไม่เลื่อนผ่านครบ โดยเฉพาะ F-11 ให้เลื่อนเฉพาะ
การตรวจรับโหลด/ความเสถียรระยะยาวและผลรวมที่ต้องพึ่งรอบนั้นไปชุดที่ 9
ตาม [ทะเบียนตรวจรับ](../roadmap.md#ทะเบียนงานค้างสำหรับชุดที่-9)
ด่านอื่นที่ยังล้มต้องแก้ก่อน merge ห้าม skip/xfail หรือลดเกณฑ์ CI เพื่อให้ผ่าน
ผล Failed/Partial ของการตรวจรับที่เลื่อนต้องเก็บไว้ ไม่แปลงเป็น Passed
การเลื่อน feature อื่นต้องระบุรายการและได้รับอนุมัติเฉพาะ ไม่ใช่สิทธิ์เลื่อนทุกเทสต์

การ merge นี้ไม่รับรองพร้อมใช้งานจริง ไม่อนุญาต production activation หรือ Completed
จนผ่าน validation ครบ และยังต้องให้เจ้าของสั่ง commit/push/merge ตามขั้นตอนเดิม
ข้อกำหนดนี้แทนข้อความเก่าที่ผูกการตรวจรับระยะยาวทั้งหมดกับ merge เท่านั้น

| ด่าน | ตรวจอะไร |
|---|---|
| รูปแบบและ lint | โค้ดสะอาดตามมาตรฐาน |
| ตรวจชนิดข้อมูล | เข้มที่สุดกับโค้ดที่คำนวณเงิน |
| ขอบเขตสถาปัตยกรรม | import-linter ตามกฎใน `architecture.md` |
| เทสต์ | ด่านก่อน merge ผ่านทั้งหมด; ด่านตรวจรับที่เจ้าของอนุมัติเลื่อนติดตามในชุดที่ 9 |

## 2. โค้ดที่คำนวณเงิน

ทุกฟังก์ชันที่คิดเงินต้องมี **ทั้งสองอย่าง**:
1. **เทสต์ด้วยตัวเลขจริง** ที่คำนวณมือแล้วเทียบ พร้อมเขียนที่มาของคำตอบไว้
2. **เทสต์คุณสมบัติ** (hypothesis) ที่พิสูจน์กฎที่ต้องจริงเสมอ เช่น ปิดไม้หมดแล้ว
   ยอดต้องกลับมาตรง, ปิดครึ่งเดียวกำไรต้องได้ครึ่งหนึ่ง

**เวลาเขียนเทสต์ ให้คิดสูตรขึ้นมาใหม่เอง ห้ามลอกจากโค้ดที่กำลังทดสอบ**
ไม่เช่นนั้นเทสต์จะแค่ยืนยันว่าโค้ดทำสิ่งที่มันทำ

## 3. ความบริสุทธิ์ของ core

ต้องมีเทสต์ที่ตรวจโดยอัตโนมัติว่า `core` ไม่มี:
- การอ่านนาฬิกา, ค่าสุ่ม, การอ่านไฟล์, การต่อเครือข่าย
- การใช้ `float` ที่ไหนก็ตาม

**ถ้าเทสต์พวกนี้แดง ให้แก้โค้ด ไม่ใช่แก้เทสต์**

## 4. ความปลอดภัยการเทรด

ต้องมีเทสต์ที่พิสูจน์ว่า:
- ออเดอร์ Paper ไม่เคยเรียกเครือข่ายออกไปข้างนอก
- คำสั่งซ้ำไม่ทำให้เกิดออเดอร์สองใบ
- **ทุกเส้นทางการสั่งออเดอร์ผ่านจุดตรวจ ไม่มีทางลัด** รวมคำสั่งลดความเสี่ยง
  ซึ่งผ่านจุดตรวจเดียวกันแต่ใช้เกณฑ์ต่างกัน ไม่ใช่ข้ามจุดตรวจ
- Live ไม่เปิดเองจากค่าตั้งต้น

เพิ่มจากกฎที่ตัดสินเมื่อ 2026-09-26 — ต้องมีเทสต์ทุกข้อนี้ด้วย:

| ต้องพิสูจน์ | มาจาก `trading-safety.md` |
|---|---|
| คำสั่งลดความเสี่ยง **ไม่ถูกปฏิเสธ** เมื่อกระเป๋าเกินเพดานอยู่ก่อนแล้ว | หัวข้อ 3 |
| คำสั่งลดความเสี่ยงส่งออกไปพร้อมธง **reduce-only** เสมอ | หัวข้อ 3 |
| คำสั่งที่ขนาดเกิน position ที่ถืออยู่ ถูกตรวจแบบคำสั่งเปิดไม้ใหม่ | หัวข้อ 3 |
| กดหยุดแล้วบอทหยุดจริง, ออเดอร์ค้าง **ทั้งของบอทและของผู้ใช้** ถูกยกเลิก **ยกเว้น TP/SL** | หัวข้อ 8 |
| คำสั่งเพิ่มความเสี่ยงในคิวถูกทิ้งและเปลี่ยนสถานะ ไม่ค้างสถานะ "กำลังจะส่ง" | หัวข้อ 8 |
| คำสั่งลดความเสี่ยงในคิวยังถูกส่งต่อ | หัวข้อ 8 |
| **สถานะหยุดรอดการ restart** และแยกได้ว่าหยุดเพราะอะไร | หัวข้อ 8 |
| ไม่มีบันทึกสาเหตุ → ถือว่ายังหยุด | หัวข้อ 8, 10 |
| BOT หลังหยุด → ประเภทยังเป็น BOT และเปิดไม้ใหม่ด้วยมือไม่ได้ | หัวข้อ8 · mission หัวข้อ5 |
| MANUAL หลังหยุด → เปิดไม้ใหม่ได้เฉพาะเมื่อผ่าน safety gates เดิม; ไม่รันบอท | หัวข้อ8 |
| ทุกประเภทหลังหยุด → ปิด/ลด position และยกเลิกออเดอร์ได้; คำสั่งเกิน position ใช้กฎเพิ่มความเสี่ยงเดิม | หัวข้อ3,8 |
| เปลี่ยน BOT→MANUAL เมื่อบอทยังทำงาน/มีออเดอร์ค้าง/มี position หรือหลักฐานไม่ครบ → ปฏิเสธ | mission หัวข้อ5 |
| ตั้ง TP/SL ไม่สำเร็จ → เทรดมือไม่ถูกปิดไม้ / บอทถูกปิดไม้คืนและหยุด | หัวข้อ 11 |
| ออเดอร์เข้าบางส่วน → TP/SL ตั้งตามขนาดที่เข้าจริงทันที ไม่รอครบ | หัวข้อ 11 |
| ชนเพดานขาดทุน → บอทหยุดและยังเลือก BOT; manual opening ไม่ได้รับสิทธิ์จากการหยุด และคำสั่งลดความเสี่ยงยังส่งได้ | หัวข้อ 13 |
| รีเซ็ตเพดานแล้วเริ่มนับจากศูนย์ ไม่นับขาดทุนค้างของไม้เดิม | หัวข้อ 13 |
| **Paper ใช้กฎเพดานชุดเดียวกับ Live** ผลต้องเหมือนกัน | หัวข้อ 13 |

| เหรียญที่ถูกถอนจากรายการ → เปิดไม้ใหม่ไม่ได้ แต่ปิดไม้เดิมได้ | `mission.md` หัวข้อ 6 |

## 5. การต่อกับ Binance

- เทสต์ปกติ **ห้ามยิงไป Binance จริง** ใช้ข้อมูลตอบกลับที่บันทึกไว้
- ตลาดเดียวของระบบคือ **Binance TH** (`/api/v1`) ไม่ทำ Binance.com
- ต้องมีเทสต์แยกที่ตรวจว่ารูปแบบข้อมูลของ Binance ยังเหมือนเดิม รันเป็นระยะ ไม่ใช่ทุกครั้งที่ push
- **ไม่ใช้ Testnet** (เจ้าของตัดสิน 2026-09-26) จึงไม่มีขั้นทดสอบกับตลาดจำลอง
  ก่อนเงินจริง — น้ำหนักจึงตกอยู่ที่เทสต์อัตโนมัติและ Paper Trading ทั้งหมด
  และการเริ่มใช้เงินจริงต้องเริ่มด้วยจำนวนน้อยและมีคนเฝ้า (`roadmap.md` F-25)
