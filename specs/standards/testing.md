# Standard — Testing

สถานะ: **Proposed**

---

## 1. ต้องเขียวก่อน merge

ไม่มีข้อยกเว้น ไม่มีการ merge ทั้งที่แดงแล้วบอกว่าจะแก้ทีหลัง

| ด่าน | ตรวจอะไร |
|---|---|
| รูปแบบและ lint | โค้ดสะอาดตามมาตรฐาน |
| ตรวจชนิดข้อมูล | เข้มที่สุดกับโค้ดที่คำนวณเงิน |
| ขอบเขตสถาปัตยกรรม | import-linter ตามกฎใน `architecture.md` |
| เทสต์ | ทั้งหมดผ่าน |

## 2. โค้ดที่คำนวณเงิน

ทุกฟังก์ชันที่คิดเงินต้องมี **ทั้งสองอย่าง**:
1. **เทสต์ด้วยตัวเลขจริง** ที่คำนวณมือแล้วเทียบ พร้อมเขียนที่มาของคำตอบไว้
2. **เทสต์คุณสมบัติ** (hypothesis) ที่พิสูจน์กฎที่ต้องจริงเสมอ เช่น ปิดไม้หมดแล้ว
   ยอดต้องกลับมาตรง, ปิดครึ่งเดียวกำไรต้องได้ครึ่งหนึ่ง

**เวลาเขียนเทสต์ ให้คิดสูตรขึ้นมาใหม่เอง ห้ามลอกจากโค้ดที่กำลังทดสอบ**
ไม่เช่นนั้นเทสต์จะแค่ยืนยันว่าโค้ดทำสิ่งที่มันทำ

## 3. ความบริสุทธิ์ของ core

ต้องมีเทสต์ที่ตรวจโดยอัตโนมัติว่า `core` ไม่มี:
- การอ่านนาฬิกา, ค่าสุ่ม, การอ่านไฟล์, การต่อเครือข่าย
- การใช้ `float` ที่ไหนก็ตาม

**ถ้าเทสต์พวกนี้แดง ให้แก้โค้ด ไม่ใช่แก้เทสต์**

## 4. ความปลอดภัยการเทรด

ต้องมีเทสต์ที่พิสูจน์ว่า:
- ออเดอร์ Paper ไม่เคยเรียกเครือข่ายออกไปข้างนอก
- คำสั่งซ้ำไม่ทำให้เกิดออเดอร์สองใบ
- ทุกเส้นทางการสั่งออเดอร์ผ่านการตรวจความเสี่ยง ไม่มีทางลัด
- Live ไม่เปิดเองจากค่าตั้งต้น
- หยุดฉุกเฉินแล้วบอทหยุดจริงและออเดอร์ที่ค้างถูกยกเลิกจริง

## 5. การต่อกับ Binance

- เทสต์ปกติ **ห้ามยิงไป Binance จริง** ใช้ข้อมูลตอบกลับที่บันทึกไว้
- ต้องมีเทสต์แยกที่ตรวจว่ารูปแบบข้อมูลของ Binance ยังเหมือนเดิม รันเป็นระยะ ไม่ใช่ทุกครั้งที่ push
- ก่อนเปิด Live จริง ต้องผ่านการทดสอบบน Testnet ก่อน

## 6. ทุก feature ต้องมี validation.md

บอกไว้ล่วงหน้าว่า "เสร็จ" หมายถึงอะไร และตรวจอย่างไร — เขียนก่อนลงมือทำ ไม่ใช่เขียนตามหลัง
