# F-06 — ตรวจคำรับรองว่า validation ผ่านครบ

วันที่: 2026-10-04
โค้ดที่ตรวจ: `3c0091f` บน `feature/f-06-totp`
ขอบเขต: `specs/features/2026-10-03-totp-2fa/validation.md`, โค้ดปัจจุบัน และเทสต์ที่มีอยู่

**ผล: ยังผ่านไม่ครบ** แม้เทสต์ที่มีอยู่เขียวทั้งหมด พบพฤติกรรมผิดเกณฑ์ผ่าน HTTP จริงสองข้อ และช่องว่างในหลักฐานหลายข้อ รายงานนี้เป็นผลตรวจ ไม่แก้เกณฑ์ที่อนุมัติแล้ว และไม่ได้แก้ production code

## 1. พฤติกรรมที่ไม่ผ่านจริง

| เกณฑ์ | หลักฐานจาก HTTP + PostgreSQL จริง | ผล |
|---|---|---|
| **V-43** | เปิด TOTP บนเครื่อง A → เครื่อง B login ด้วย recovery code ได้ 200 → กลับไปใช้ cookie ของ A เรียก `/auth/me` ยังได้ **200**; เกณฑ์กำหนดให้ได้ **401** | **ไม่ผ่าน** — `complete_sign_in()` ออก session/สิทธิ์กู้/บันทึกการใช้รหัส แต่ไม่มี `end_others()` ในทาง recovery login |
| **V-46 (กรณี recovery login)** | ทางเดียวกับ V-43 ไม่มีทั้งการเพิกถอนและการลง `ALL_SESSIONS_ENDED` พร้อมจำนวนใน transaction นั้น | **ไม่ผ่านในกรณีนี้**; ไม่เหมารวมว่าอีกสามกรณีเสีย |
| **V-61.2** | ใช้รหัส TOTP ปัจจุบันที่ `/auth/totp/recovery-codes` สำเร็จ **200** → ยิงรหัสเดิมอีกครั้งได้ **403** พร้อมข้อความ `ต้องยืนยันด้วยรหัสจากแอปยืนยันตัวตน` | **ไม่ผ่าน** — ไม่มีคำแนะนำให้รอรหัสช่วงใหม่; frontend แสดงข้อความปฏิเสธที่ API ส่งมา |

การปฏิเสธ replay ทำงาน แต่ไม่ผ่านเกณฑ์เรื่องข้อความ ไม่ใช่ข้อบกพร่องว่า replay ถูกยอมรับ

สคริปต์ตรวจในรอบนี้: `/private/tmp/f06-validation-probe.py` รันผ่าน `/private/tmp/tiewtrade-f06-check.py`; สร้างบัญชีทดสอบใหม่และใช้ TestClient lifespan จริง แสดงเฉพาะ HTTP status กับข้อความปฏิเสธ ไม่แสดง secret หรือ recovery code

## 2. เทสต์เขียวแต่ยังพิสูจน์ไม่ครบตามวิธีตรวจที่อนุมัติ

การขาดเทสต์ในตารางนี้ไม่ใช่หลักฐานว่าโค้ดมีบั๊ก แต่ยังใช้รับรองว่าเกณฑ์ผ่านครบไม่ได้

| เกณฑ์ | ช่องว่างที่พบ |
|---|---|
| **V-5** | `test_the_confirmed_secret_is_never_returned_again` ตรวจเพียง `/auth/me` และ `/health`, ค้น bytes/hex ใน body; ไม่เดินทุกเส้นทางและ header ไม่ค้น base32 ของ secret ที่ยืนยันแล้ว |
| **V-6** | canary ของ F-05 ทดสอบรหัสผ่าน/token และของ F-03 ทดสอบค่าที่ bind; ไม่พบเทสต์บังคับ unseal ของ TOTP ล้มเหลวแล้วค้น secret ใน traceback ทั้งก้อนตามที่ข้อนี้กำหนด |
| **V-11.2, V-24.1, V-38** | ไม่พบการฉีดความล้มเหลวกลาง transaction ของ confirm/login/การออก recovery set แล้วตรวจผล rollback ที่เกณฑ์ระบุ; wrong-code test ของ login ไม่ใช่ความล้มเหลวหลังออก session ก่อน commit |
| **V-18** | มีการกัน replay ที่ระดับโมดูล แต่ไม่พบเทสต์ HTTP แยกคู่ login → reverify/disable/replace ตามเกณฑ์ |
| **V-20.1, V-20.2, V-20.3** | เทสต์ secret เก่าทดสอบการ verify ใหม่หลังเปลี่ยน ซึ่งไม่แยกพิสูจน์เงื่อนไข `secret_version` ด้วยตัวเอง; race ใช้ gather รอบเดียว ไม่บังคับทั้งสองลำดับ และไม่พบ assertion ค่าทั้ง version/accepted step หลังสลับตาม V-20.3 |
| **V-21, V-22** | ขั้นแรกตรวจว่าไม่มี session cookie แต่ไม่ assert ว่าไม่มี session row; challenge test ยิงเพียง `/auth/me` กับ `/auth/logout` ไม่เดินทุก protected route โดยส่ง challenge เป็น session cookie |
| **V-25** | ไม่พบการวัดเวลาตอบครบสี่กรณีที่ระบุ โดยแยกบัญชีที่เปิด/ไม่เปิด TOTP |
| **V-26.3** | ไม่พบ race test ระหว่างการเปลี่ยนรหัสผ่านกับการใช้ challenge ทั้งสองลำดับ; test setup/confirm race ที่เพิ่มล่าสุดเป็นคนละกรณี |
| **V-41.5.1** | เทสต์ session หมดอายุปรับเฉพาะ idle deadline และตรวจ RLS; ยังไม่ครอบ absolute deadline และ HTTP ใช้สิทธิ์ทั้งสองกรณีตามเกณฑ์ |
| **V-52** | เทสต์ crypto แยก associated data ของงานจำลอง แต่ยังไม่ได้พิสูจน์สิทธิ์อ่านคอลัมน์ secret ของตลาดจริง เพราะยังเป็นงาน F-07; ต้องระบุขอบเขตหลักฐานนี้ให้ตรง |
| **V-58** | เทสต์เพียง enum ว่าไม่มีชื่อ FAILED/WRONG; ไม่ยิงรหัสผิดผ่าน HTTP แล้วนับ audit rows ว่าไม่เพิ่ม |
| **V-62.5** | เทสต์ชื่อ `test_the_quota_is_not_cleared_by_success` ไม่ได้ยืนยันสำเร็จจริง: มันเรียก `clear()` แล้ว assert ว่าได้โควตากลับมา; ส่วน `forget_account()` test ครอบ V-62.8 แต่ยังไม่แทน success flow ที่ V-62.5 ต้องการ |

V-62.1/V-62.3/V-62.6 มีหลักฐานกลไกถังจริงและการยิงพร้อมกันที่ระดับฐานข้อมูล ส่วน V-62.2 ใหม่เดิน HTTP และเปลี่ยน actual client IP แล้ว ช่วยปิดช่องเดิมเรื่อง account quota ได้ แต่ไม่ทำให้ V-62.5 ผ่านตามไปด้วย

V-31/V-62.4 มีข้อจำกัดว่าระบบยังไม่มีเส้นทางลดความเสี่ยงจริง เทสต์ปัจจุบันตรึงตาราง/กฎประเภทไว้ จึงไม่ใช่หลักฐาน HTTP ของเส้นทางการเทรดที่ยังไม่เกิดขึ้น ตามข้อจำกัดที่ spec บันทึกไว้
