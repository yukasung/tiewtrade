# F-08 ทะเบียนกระเป๋าและการผูก API key — Requirements

สถานะ: **Superseded** — เจ้าของอนุมัติเอกสารฉบับปรับปรุง 2026-10-07
วันที่: 2026-10-07
Branch: `feature/f-08-sub-account-wallets` — สร้างจาก F-07 commit `7efbbfb` ตามคำสั่งเจ้าของ 2026-10-07

## ทำไมต้องมี

F-07 จัดการ API key ของผู้ใช้ได้แล้ว แต่ยังไม่มีทะเบียนกระเป๋าที่ผูก key และ
ระบุว่าจะใช้เทรดมือหรือบอท F-08 เพิ่มทะเบียนนี้เพื่อเตรียมงานถัดไป โดยแยก
การตรวจว่า key ใช้งานได้ออกจากการพิสูจน์ว่า key เป็นของบัญชีจริงใด

เจ้าของตกลง 2026-10-07 ให้เดินหน้าผูก key ก่อน โดยแสดงว่า
**ยังไม่ยืนยันบัญชีจริง** และยังไม่ใช้กระเป๋าเหล่านี้ส่งออเดอร์หรือรันบอท
การผูก key ในงานนี้จึงไม่ใช่การรับรองว่าแยกเงินจริงระหว่างบัญชีสำเร็จแล้ว

## ขอบเขต

### ทำ

- ผู้ใช้สร้างและดูทะเบียนกระเป๋าของตัวเอง เลือกเทรดมือหรือบอทตอนสร้าง
- ผู้ใช้เตรียมบัญชีและ key บน Binance TH เอง แล้วเลือก key ของตัวเองที่ F-07 ตรวจผ่านมาผูก
- กัน key เดิมผูกมากกว่าหนึ่งกระเป๋า แม้ key นั้นถูกบันทึกเป็นคนละแถว
- แสดงสถานะการผูก key และข้อความว่าบัญชีจริงยังไม่ผ่านการยืนยัน
- ลบ key แล้วคงกระเป๋าและประวัติ พร้อมสถานะยังไม่เชื่อมต่อ
- ใช้กฎข้อมูลผู้ใช้ การเข้ารหัส TOTP และการบันทึก audit เดิม

### ไม่ทำใน F-08

- แสดงยอด อัปเดตยอดเรียลไทม์ หรือเกณฑ์ความหน่วง 1 วินาที
- พิสูจน์รหัสบัญชีจริง หรืออ้างว่ากัน key ต่างกันของบัญชีเดียวกันได้
- รับ key ใหม่แทน key เดิมในกระเป๋าเดิม ก่อนพิสูจน์ว่าเป็นบัญชีเดิมได้
- ส่งออเดอร์ รันบอท เปิด Live สร้างบัญชีย่อย โอนหรือถอนเงิน
- เงินตั้งต้น Paper (F-13) และ Futures (NC-12)

และไม่ทำให้ประวัติเดิมย้ายไปกระเป๋าใหม่

## การเปลี่ยนขอบเขตที่เจ้าของตกลง (2026-10-07)

1. เพดาน 6 กระเป๋า และสูงสุด 1 บอทต่อกระเป๋า
2. เลือกเทรดมือ/บอทตอนสร้าง และเปลี่ยนประเภทได้เมื่อเงื่อนไข RQ-14 ผ่าน
3. ถอนการแสดงยอด/เรียลไทม์จาก F-08
4. เลือกผูก key ที่ตรวจผ่าน แต่ยังไม่ยืนยันบัญชีจริง แทนการรอคำตอบ Binance TH
5. กัน key เดิมซ้ำ แต่ไม่รับรองบัญชีเดียวกันที่ใช้ key ต่างกัน
6. ยังไม่เปลี่ยน key ในกระเป๋าเดิม; คงทะเบียน/ประวัติหลังลบ key
7. เลื่อน NC-21 และการพิสูจน์บัญชีจริงไปก่อนใช้กระเป๋าเทรด โดยคงข้อห้ามย้ายเงิน

ไม่ใช้ชื่อบัญชี รหัสบัญชีที่ผู้ใช้กรอกเอง หรือยอดที่ตรงกันเป็นหลักฐานว่า key
อยู่ในบัญชีจริงเดียวกัน งานนี้ไม่ต้องเรียก broker หรือจัดการบัญชีย่อยเพื่อผูก key

## ของเดิมที่พบสำหรับขั้นวางแผน

- `backend/src/tiewtrade/infra/api_keys/records.py` — สถานะ key และข้อมูลสรุปที่ไม่พาความลับ
- `backend/src/tiewtrade/infra/api_keys/storage.py` — จัดเก็บ รายการ และลบ key
- `backend/src/tiewtrade/services/engine/verification.py` — พิสูจน์ว่า key ใช้งานได้
- `backend/src/tiewtrade/services/api/routing_policy.py` — กฎการยืนยันซ้ำของ route
- `backend/src/tiewtrade/venues/wallets.py` — WalletSource/Quantity สำหรับการพิสูจน์ key เดิม
- `backend/src/tiewtrade/venues/binance_th/wallets.py` — ตัวเชื่อมอ่านบัญชีที่ F-07 ใช้อยู่

รายการนี้เป็นข้อมูลสำหรับ plan ภายหลัง ไม่ใช่การอนุมัติ implementation
